---
title: Environment variables
description: Every variable that configures a Carbon instance, grouped by concern. The source of truth is packages/env.
---

Carbon reads its configuration from environment variables. The registry lives in `packages/env`;
`.env.example` is the template; infrastructure-only variables are read by `sst.config.ts`. A minimal
instance needs the Carbon API/database connection, a session secret, and Redis. Everything else activates
features as you need them.

## Core

Platform-wide behavior and edition.

<EnvVars>
<EnvVar name="CARBON_EDITION" type="enum">One of `community`, `cloud`, `enterprise`, or `test`. Gates edition-specific features.</EnvVar>
<EnvVar name="CONTROLLED_ENVIRONMENT" type="boolean">Enables ITAR / controlled-environment restrictions.</EnvVar>
<EnvVar name="AUTH_PROVIDERS" type="enum[]">Allowed sign-in methods: `email`, `google`, `azure`, `passkey`.</EnvVar>
<EnvVar name="DOMAIN" type="string">Base domain the apps are served from.</EnvVar>
<EnvVar name="ERP_URL" type="url">Public URL of the ERP app.</EnvVar>
<EnvVar name="MES_URL" type="url">Public URL of the MES app.</EnvVar>
<EnvVar name="DEFAULT_LANGUAGE" type="string">Default UI language.</EnvVar>
<EnvVar name="RATE_LIMIT" type="number">Requests per window allowed against the API.</EnvVar>
</EnvVars>

## API & database

Carbon's API endpoint, auth signing keys, and single Postgres database. All five are required.

<EnvVars>
<EnvVar name="CARBON_API_URL" type="url" required>Carbon API base URL.</EnvVar>
<EnvVar name="CARBON_PUBLIC_KEY" type="string" required>Public auth/API key, browser-safe.</EnvVar>
<EnvVar name="CARBON_SERVICE_ROLE_KEY" type="string" required>Service-role key, server only, never exposed to the client.</EnvVar>
<EnvVar name="CARBON_DATABASE_URL" type="url" required>Direct Postgres connection string.</EnvVar>
<EnvVar name="CARBON_AUTH_JWT_SECRET" type="string" required>Secret used to sign and verify session JWTs.</EnvVar>
</EnvVars>

Legacy deployments may still provide `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`,
`SUPABASE_DB_URL`, and `SUPABASE_JWT_SECRET`; Carbon treats them as fallback aliases while the
self-hosted data plane is being migrated.

## Object storage

Carbon stores files through an S3-compatible object store. The Docker with Caddy recipe wires these
to its bundled MinIO service and generates the access keys as Docker secrets.

<EnvVars>
<EnvVar name="CARBON_STORAGE_ENDPOINT" type="url" required>S3-compatible endpoint used for uploads, downloads, and signed URLs.</EnvVar>
<EnvVar name="CARBON_STORAGE_REGION" type="string">S3 region. Defaults to `us-east-1`.</EnvVar>
<EnvVar name="CARBON_STORAGE_BUCKET" type="string">Optional shared bucket. When set, Carbon stores logical buckets as key prefixes inside this bucket.</EnvVar>
<EnvVar name="CARBON_STORAGE_BUCKET_PREFIX" type="string">Prefix for physical bucket names when `CARBON_STORAGE_BUCKET` is not set.</EnvVar>
<EnvVar name="CARBON_STORAGE_FORCE_PATH_STYLE" type="boolean">Use path-style S3 URLs. Required for the bundled MinIO service.</EnvVar>
<EnvVar name="CARBON_STORAGE_ACCESS_KEY_ID" type="string">S3 access key id. The Docker with Caddy recipe injects this from `minio_access_key`.</EnvVar>
<EnvVar name="CARBON_STORAGE_SECRET_ACCESS_KEY" type="string">S3 secret access key. The Docker with Caddy recipe injects this from `minio_secret_key`.</EnvVar>
<EnvVar name="CARBON_STORAGE_PUBLIC_URL" type="url">Public base URL for rendering stored file paths.</EnvVar>
</EnvVars>

## Auth & sessions

<EnvVars>
<EnvVar name="SESSION_SECRET" type="string" required>Signs the session cookie.</EnvVar>
<EnvVar name="CARBON_AUTH_EXTERNAL_GOOGLE_CLIENT_ID" type="string">Google OAuth client id, when `google` is in `AUTH_PROVIDERS`.</EnvVar>
<EnvVar name="CARBON_AUTH_EXTERNAL_GOOGLE_CLIENT_SECRET" type="string">Google OAuth client secret, when `google` is enabled.</EnvVar>
<EnvVar name="CARBON_AUTH_EXTERNAL_AZURE_CLIENT_ID" type="string">Azure OAuth client id, when `azure` is enabled.</EnvVar>
<EnvVar name="CARBON_AUTH_EXTERNAL_AZURE_CLIENT_SECRET" type="string">Azure OAuth client secret, when `azure` is enabled.</EnvVar>
<EnvVar name="DEV_BYPASS_EMAIL" type="string">Local only. Sign in as this email without a magic link.</EnvVar>
</EnvVars>

Configure OAuth providers with the app's Better Auth callback route:
`/api/auth/callback/google` for Google and `/api/auth/callback/microsoft` for Microsoft.

Sign-in bot protection uses Cloudflare Turnstile: `CLOUDFLARE_TURNSTILE_SITE_KEY` and
`CLOUDFLARE_TURNSTILE_SECRET_KEY`.

## Jobs & cache

<EnvVars>
<EnvVar name="REDIS_URL" type="url" required>Redis connection (ioredis URL) for the permission cache and queues.</EnvVar>
<EnvVar name="INNGEST_SIGNING_KEY" type="string">Signs requests to the Inngest jobs runner. Required in production.</EnvVar>
<EnvVar name="INNGEST_EVENT_KEY" type="string">Key for sending events to Inngest. Required in production.</EnvVar>
<EnvVar name="INNGEST_BASE_URL" type="url">Override the Inngest endpoint (self-hosted or dev).</EnvVar>
</EnvVars>

<Callout type="warn" title="Inngest keys are required in production">
`INNGEST_SIGNING_KEY` and `INNGEST_EVENT_KEY` are only optional in development, where `INNGEST_DEV=1` is set. Without `INNGEST_DEV`, the app fails to boot if either is missing, and no background jobs (MRP, scheduling, notifications, integration syncs) or queued events run. A self-hosted Inngest server supplies both. The Docker with Caddy recipe generates them for you.
</Callout>

## Infrastructure — SST

Read by `sst.config.ts` at deploy time, not by the app.

<EnvVars>
<EnvVar name="AWS_REGION" type="string" required>Region to deploy into.</EnvVar>
<EnvVar name="AWS_ACCOUNT_ID" type="string" required>Target AWS account.</EnvVar>
<EnvVar name="IMAGE_TAG" type="string" required>ECR image tag to deploy.</EnvVar>
<EnvVar name="CERT_ARN_ERP" type="string">ACM certificate ARN for the ERP domain.</EnvVar>
<EnvVar name="CERT_ARN_MES" type="string">ACM certificate ARN for the MES domain.</EnvVar>
<EnvVar name="URL_ERP" type="url">Custom ERP domain, overrides the default.</EnvVar>
<EnvVar name="URL_MES" type="url">Custom MES domain, overrides the default.</EnvVar>
</EnvVars>

<Callout type="warn">
Older notes list `TRIGGER_*` (Trigger.dev) and `UPSTASH_REDIS_*` variables. Those are gone. Jobs run on
Inngest and the cache uses a plain `REDIS_URL`.
</Callout>
